6. Customer Enquiry and Lead Management System

Implement a functional lead management module.

Lead lifecycle

1. Visitor opens a service or project page.
2. Visitor submits an enquiry.
3. Frontend validates the information.
4. Backend validates and sanitizes the request.
5. Lead is stored in PostgreSQL.
6. System generates a unique lead reference.
7. Customer sees a confirmation message.
8. Authorized staff can review and update the lead.

Lead statuses

- New
- Contacted
- Follow-up Required
- Qualified
- Converted
- Closed

Each lead record should include:

- Unique ID
- Customer name
- Contact information

- Enquiry description
- Consent record
- Creation timestamp
- Assigned staff member
- Current status
- Follow-up notes

Implement pagination, filtering, search, and status updates in the administration interface.

8. Backend API Design

Implement versioned REST APIs using the "/api/v1" prefix.

Suggested endpoints:

Public APIs

- "GET /api/v1/services"
- "GET /api/v1/services/{slug}"
- "GET /api/v1/projects"
- "GET /api/v1/projects/{slug}"
- "GET /api/v1/partners"
- "POST /api/v1/enquiries"
- "GET /api/v1/site-settings/public"

Authentication

- "POST /api/v1/auth/login"
- "POST /api/v1/auth/logout"
- "GET /api/v1/auth/me"

Protected administration APIs

- "GET /api/v1/admin/enquiries"
- "GET /api/v1/admin/enquiries/{id}"
- "PATCH /api/v1/admin/enquiries/{id}"
- "GET /api/v1/admin/dashboard"
- CRUD endpoints for projects, services, partners, and site settings

All protected endpoints must verify authentication and permissions on the server.

Add API documentation through FastAPI's OpenAPI/Swagger interface in development. Restrict or disable sensitive documentation in production as appropriate.
